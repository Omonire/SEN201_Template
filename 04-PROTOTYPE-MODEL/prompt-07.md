## Stage 2 - Present the assigned model and the predefined scenario

This prompt ships with one predetermined project context. The case study is deliberately specific; do not generalise it away.

**Assigned SDLC model:** Prototype Model

**Case study domain:** Agriculture

### Predefined scenario

AgriLedger, a rural cooperative digital-records project. Farmers are interested in recording activities but the team is unsure which records they value and how they will enter data. A simple prototype must be tested in the field before the data model and interface are fixed.

### Project requirements

- Record planting, input use and harvest events per plot.
- Capture photos of inputs or receipts.
- Show a simple seasonal timeline of activities.
- Produce a summary that farmers can share with buyers.
- Work offline and synchronise later.

### Project objectives

- Help farmers keep useful, low-effort records.
- Discover which data fields farmers actually value.
- Test offline usability under field conditions.

### Stakeholders

- Smallholder farmers
- Cooperative officers
- Extension agents
- Field researchers
- UI designers
- Buyers

### Expected outcomes

- A field-tested prototype with a refined data model.
- Agreed minimal record set based on farmer feedback.
- Validated offline interaction requirements.

### Analytical note on the model-scenario pairing

The data model depends on what farmers find worth recording, which is not obvious to developers. A prototype tested in real field conditions reveals these priorities early, allowing the specification to be shaped by evidence rather than guesswork.

Present this information to the student clearly. Confirm that the model and scenario are understood before proceeding to research. The pairing note is guidance for your analysis; the final documents must develop the reasoning in the student's own academic voice.

## Stage 9 - Compulsory draw.io structural diagram

**Required diagram:** Prototype Feedback Loop Diagram

draw.io is a free, browser-based diagramming tool available at https://app.diagrams.net/ . It is also known as diagrams.net and can be used online or installed as a desktop application. It is appropriate for Software Engineering diagrams because it provides a wide range of standard shapes, connectors and labelled arrows, supports precise layout, allows diagrams to be saved or exported in common formats and produces a shareable live link. These features make it well suited to representing phase structures, workflows and relationships in an SDLC model.

The structural diagram you must describe to the student is designed to show a cyclical discovery process in which an early model is demonstrated to users, their feedback is collected and the prototype is revised until requirements are sufficiently clear for the final system to be specified and built.

Explain each of the following in the main assignment and expand on them in the explanation guide:

- Important shapes: Rounded rectangles for the main activities, a display or screen symbol for the prototype, a person symbol for users and a decision diamond for the requirement-clarity check.
- Required labels: Identify Initial Requirements, Build Quick Prototype, Demonstrate to Users, Collect Feedback, Revise Prototype, Requirements Clear?, Specify and Build Final System.
- Arrows and connections: Clockwise arrows forming a loop from identify to build to demonstrate to collect to revise and back; a labelled Yes arrow from the diamond to final system development and a No arrow back to Build Quick Prototype.
- How to read the diagram: Trace the loop clockwise. The repeated passes are not full product releases; they are refinements of a partial artefact used to elicit requirements. The loop ends only when the clarity decision is Yes, after which the final system is specified.

Give the student clear step-by-step drawing guidance:

1. Arrange five rounded rectangles in a clockwise circle and label them with the first five activities.
2. Insert a screen symbol between Build Quick Prototype and Demonstrate to Users.
3. Add a user icon next to Demonstrate to Users.
4. Place a decision diamond labelled Requirements Clear? after Collect Feedback.
5. Draw a Yes arrow from the diamond to a Final System Development rectangle outside the loop.
6. Draw a No arrow from the diamond back to Build Quick Prototype and label each loop pass with the round number.
