# SEN 201 Waterfall Assignment Guide

A general guide to the SEN 201 Software Engineering assignment on the Waterfall Model.
It describes the expected structure and how to approach each section; it contains no
personal or student-specific information.

## Purpose

The assignment tests whether a software engineering model can be explained clearly and
applied convincingly to a realistic project. It is not a history exercise: the aim is to
connect the characteristics of a model to the facts of a case study.

## Assignment structure

| Section | What it should do |
|---|---|
| Introduction | Establish why process models matter in software engineering |
| Definition of a Software Engineering Model | Explain abstraction and what a process model represents |
| Overview of SDLC Models | Compare Waterfall, V-Model, Spiral, Prototype, Agile, Incremental and Iterative |
| Selected Model | Describe the chosen model accurately, including its phases |
| Case Study | Report only the facts given in the brief |
| Application | Walk through the phases using the case |
| Justification | Connect model characteristics to case facts |
| Advantages | Explain benefits with project-specific consequences |
| Structural Diagram | Explain the diagram and insert the screenshot |
| Disadvantages | Explain limitations and how they would be managed |
| Conclusion | Synthesise without introducing new material |
| References | Cite credible sources in APA 7th edition |

## The Waterfall Model

Waterfall is a linear sequential process in which each phase is completed and signed off
before the next begins. Its common phases are:

1. Requirements analysis and specification
2. System and software design
3. Implementation and unit testing
4. Integration and system testing
5. Deployment
6. Operation and maintenance

It suits projects with stable requirements, a fixed deadline and a high cost of error.
Its main weaknesses are late defect discovery, expensive change, delayed stakeholder
feedback and concentrated deployment risk.

## Typical case study pattern

A suitable Waterfall case has requirements fixed by regulation or contract, a known
delivery date and serious consequences for mistakes. Payroll, statutory reporting and
regulated financial systems are common examples. The case study should be described
using only the brief: requirements, objectives, stakeholders and expected outcomes.

## Application approach

For each phase, state what is produced, who reviews it and why the sign-off matters.
Show how artefacts flow from one phase to the next, and note where change control is
needed if a rule or requirement is revised.

## Structural diagram

Draw a phase cascade diagram with stacked phase boxes, review and sign-off gates,
downward arrows, deliverable documents at the side and a controlled change-approval
diamond. Create it manually in draw.io at <https://app.diagrams.net/> and insert the
screenshot in the main assignment. The diagram must be verified by the student before
submission.

## Research and referencing

Use textbooks, peer-reviewed publications, university resources and official
documentation. Verify titles, authors, dates and URLs, and never invent publications,
DOIs or links. Distinguish established facts from interpretation. Cite sources in-text
and provide an APA 7th edition reference list.

## Deliverables

- **Main assignment** — the submitted academic document.
- **Explanation guide** — a companion that explains section meanings, terminology,
  diagram interpretation and likely lecturer questions. It complements the assignment
  rather than repeating it.

## Academic integrity

These materials are educational guides, not answer keys. Review, verify and edit all
work before submission, and follow the lecturer's instructions and the institution's
academic integrity policies. Where they conflict with a template, the lecturer wins.
